Una clase abstracta está hecha para la herencia, siempre representa una clase padre de la cual extendemos.
Representa un concepto, NO SE DEBERÍA CREAR UNA INSTANCIA DE ESTA CLASE, sino las instancias se crean a partir de la instancia concreta o las clases hijas, que extienden de esta clase abstracta.
> [!warning] Tienen métodos abstractos, sin implementación específica.

- Cada hija sobre-escribe los métodos con una implementación única. 
- Se pone ABSTRACT en la clase como modificador.
- Está diseñada para ser una clase padre y no se puede crear una instancia, o ejemplarizar con el NEW.
```java
abstract public class Persona{
//protected para que clases hijas puedan usar estos atributos, sin necesidad de los getters
	protected Integer id; 
	protected String nombre;
	protected String apellido;
	protected String email;
	protected Date fechaRegistro;
// Los métodos no tienen cuerpo
	abstract public void registrar();
	
	abstract public void modificar();
	
	abstract public void eliminar();
}
```
- Cuando se hereda de una clase padre abstracta estamos obligados a implementar sus métodos por contrato.
- Al tener un método abstract requiere que la clase sea abstracta. Pero una clase abstracta puede tener métodos NO abstractos.
- En la clase hija se debe @override para que implemente sus métodos abstractos del padre, o poniendo la palabra abstract en la declaración de la clase se borraría el mensaje de error. Generate-> implements methods -> ok
