Es un mecanismo de POO para implementar relaciones en jerarquía de clases
- Una subclase hereda el estado y comportamiento de todos sus **ancestros**
- Es una de las bases de polimorfismo y reutilización de código.
- NO se puede aplicar herencia si no existe alguna relación entre ellas.
- Se debe usar la palabra EXTENDS
- Persona -> Profesor, Director, Alumno
- FigurasGeométricas -> Cuadrado, Rectángulo, Triángulo
- El término **superclase** se refiere a la clase que es el ancestro más directo así como a todas las clases ascendentes.
- OBJECT ES PADRE DE TODAS LAS CLASES DE FORMA IMPLÍCITA.
- Solo herendan las hijas los atributos si están en el mismo package.
- Los atributos privados de la clase padre no se heredan a las hijas, solo se pueden acceder a través del toString(), getters y setters que son public, y del constructor, esto es de forma indirecta. O si están en protected los atributos del padre. Es como un default que si están en la misma clase se pueden acceder de forma directa(sin poner get por delante), pero en este caso solo lo pueden acceder las hijas que heredan del padre. De esta última manera el principio de ocultación queda más débil.
- con protected Solo se puede acceder en las clases hijas o en las clases que esten en el mismo package.
Especialización:
- ABIERTO a la extensión (extends- herencia) CERRADO a la modificación
Generalización: 
- Crear una clase si tenemos dos que son muy parecidas, así partimos desde esa nueva clase.
Super(); 
- Una clase hija puede reutilizar los atributos y métodos de la clase padre, con this se refiere a la misma clase, y con super a la clase padre.
```java
public class Persona {
	private String nombre;
	private String apellido;

	public Persona(String nombre, String apellido) {
		this.nombre = nombre;
		this.apellido = apellido;
	}
}
// lo pasa mediante constructor que es public
public class Alumno extends Persona {
	private double promedio;

	public Alumno(String nombre, String apellido, double promedio) {
		super(nombre, apellido);// primero se llama a super
		this.promedio = promedio;
	}
	
}
```
- Se puede sobreescribir los métodos del padre, esto es polimorfismo, también se podría mantener lo mismo del padre (super)y añadir una nueva característica. Se tiene que llamar de igual manera al método hijo.
```java
@Override
	public void metodoDelPadre(){
		super.metodoDelPadre();
		[...]
	}
```
- También se puede sobreescribir el toString() del padre
```java
@Override
	public String toString(){
		return super.toString() + "promedio:" + this.promedio;
		[...]
	}
```
##### Restringuir la herencia y sobreescritura de métodos.
- También se puede evitar la sobreescritura del método a través de **final**
`final public class Persona { [...] }`
- La clase hija no puede sobreescribir los métodos del padre.
`final public void metodoDelPadre() { //doing sthg important }`
- Una clase no puede heredar de varias clases al mismo tiempo.
- SI instanciamos con la clase del tipo del padre tenemos que hacer un CAST, porque no tendrá acceso a la clase del hijo (métodos, atributos) porque está con la del padre : 
```java
import org.example.pooherencia.*;//se importen todas las clases

Persona alumno = new Alumno();
alumno.setInstitución("Instituto Richelieu");//doesn't work 
//Tenemos que hacer un cast a la variable alumno.
(Alumno)alumno.setInstitución("Instituto Richelieu");
//Para que se pueda invocar el método, es entre paréntesis
((Alumno)alumno).setInstitución("Instituto Richelieu");
//Aquí hacemos cast con su propia instancia
```
- Entonces cuando tenemos los métodos get y set del tipo alumno, no puedo acceder a él si estoy usando el tipo del padre, solo mediante el cast del tipo de la clase y usarla en la variable, con paréntesis.
- Una clase hija es tipo de sus ancestros.
